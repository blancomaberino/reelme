# T-060 — Design language: run the design-agent brief, review, and commit the visual spec

- **Phase:** M2 · **Estimate:** M · **Status:** see tasks.json
- **Depends on:** — (can run anytime; T-061 consumes the output)
- **Target paths:** `../design/` (plans repo), later mirrored into the app repo under `apps/api/public/design/`
- **Spec refs:** [../design/DESIGN-AGENT-PROMPT.md](../design/DESIGN-AGENT-PROMPT.md), [../00-product-spec.md](../00-product-spec.md)

## Context

The current `demo.html` (apps/api/public/) grew task-by-task into a functional but ugly dev
console: gray bordered sidebar cards, default Leaflet markers, emoji icons, no imagery, no
hierarchy. The user has rejected the look. Rather than iterating pixel-by-pixel in code
review, this task produces a committed **visual spec**: a self-contained HTML design
prototype (design tokens + all key screens/states) generated by a design-focused agent from
the brief at `design/DESIGN-AGENT-PROMPT.md`, then reviewed and accepted by the user.
T-061 implements it. The token block is written to be liftable into the Expo app's theme
later (T-032/T-033/T-039 screens), so this is not throwaway demo work.

## Implementation steps

1. **Run the brief.** Paste the prompt body from `design/DESIGN-AGENT-PROMPT.md` into a
   fresh design-agent session (claude.ai or Claude Code + `frontend-design` skill). This
   step is human-driven — the user runs it and curates.
2. **Iterate on taste.** 2–3 rounds max ("warmer", "bigger media", "calmer surfaces").
   Check both desktop and ~390px mobile compositions, light and dark.
3. **Review against the brief's hard constraints** before accepting: single file, no
   external requests, `:root` token block + `[data-theme="dark"]` overrides, all 7
   screen/state groups present, design-system section at the bottom, AA contrast spot-check
   (text on surfaces and on the accent).
4. **Commit the accepted prototype** as `design/reelmap-design-v1.html` in this plans repo
   (source of truth), plus a short `design/DECISIONS.md`: chosen art direction, palette
   logic, type pairing, and anything intentionally rejected (so future agents don't
   resurrect it).
5. **Extract tokens** into `design/tokens.md` (or keep as the commented `:root` block if
   clean enough) — the canonical list T-061 and the mobile theme will consume.

## Acceptance criteria

- [ ] `design/reelmap-design-v1.html` committed: opens from disk with zero network requests, shows map home (desktop + mobile), search, place detail, profile, auth/share modals, and system states
- [ ] All visual values flow from CSS custom properties in one `:root` block with a `[data-theme="dark"]` variant
- [ ] Design-system section renders swatches, type scale, buttons, chips, status pills, inputs, and pin/cluster designs
- [ ] `design/DECISIONS.md` records the chosen direction and rejected alternatives
- [ ] User has explicitly signed off on the prototype ("this is the look")

## Verification

```bash
open design/reelmap-design-v1.html          # visual pass, then toggle dark mode
grep -c 'https\?://' design/reelmap-design-v1.html   # expect 0 external asset URLs
```

Resize the browser to 390px width — the mobile compositions must hold up without
horizontal scroll.

## Gotchas

- Design agents love external Google Fonts and Unsplash URLs despite instructions — reject
  any file with network requests; it must be portable into the Laravel `public/` dir as-is.
- Don't accept a dark-only design: food imagery and daytime map use want light-primary.
- Guard against "AI-startup default" output (purple gradients, glassmorphism everywhere);
  the brief asks for a stated art direction — if the agent can't articulate one, re-roll.
- Scope discipline: this task ends at an accepted static prototype. No wiring to the API,
  no porting — that's T-061.
